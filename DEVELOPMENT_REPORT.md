# Отчёт о разработке мобильного приложения «КубМИ» для Кубанского медицинского института

## 1. Введение
Данный документ представляет собой подробный отчёт о процессе разработки мобильного приложения для Кубанского медицинского института (КубМИ). Приложение предназначено для обеспечения студентов и преподавателей оперативным доступом к расписанию занятий, новостям института и важной контактной информации.

Я разработал это приложение с нуля, ориентируясь на современные стандарты разработки под ОС Android, обеспечивая высокую производительность, надежность и удобство пользовательского интерфейса.

## 2. Функциональные возможности приложения
Приложение реализует следующий набор функций:
*   **Просмотр расписания студентов:** выбор группы и просмотр актуального расписания на неделю.
*   **Просмотр расписания преподавателей:** поиск по ФИО преподавателя и отображение его нагрузки.
*   **Новостная лента:** автоматический сбор новостей с официального сайта института.
*   **Информационный раздел «Об институте»:** история, руководство, факультеты и контакты.
*   **Режим киоска (Kiosk Mode):** возможность фиксации приложения на экране для использования на информационных панелях в холле института.
*   **Админ-панель:** защищенный раздел для управления настройками приложения и очистки кэша.
*   **Автономная работа:** сохранение данных в локальную базу данных для доступа без интернета.

## 3. Технологический стек
Для реализации проекта были выбраны следующие технологии:
*   **Язык программирования:** Kotlin (современный стандарт Android-разработки).
*   **UI Framework:** Jetpack Compose (декларативный подход к созданию интерфейсов).
*   **Архитектура:** MVVM (Model-View-ViewModel) в сочетании с элементами Clean Architecture.
*   **Инъекция зависимостей:** Hilt (на базе Dagger 2).
*   **Локальная БД:** Room (библиотека над SQLite).
*   **Работа с сетью и парсинг:** Jsoup (для веб-скрейпинга), Retrofit (подготовка к API), OkHttp.
*   **Асинхронность:** Kotlin Coroutines & Flow.
*   **Фоновые задачи:** WorkManager.
*   **Логирование:** Timber.
*   **Безопасность:** Jetpack Security (EncryptedSharedPreferences).

## 4. Архитектура приложения
Приложение построено на базе многослойной архитектуры для обеспечения тестируемости и расширяемости:

1.  **Data Layer (Слой данных):**
    *   `WebScraper`: отвечает за извлечение данных из HTML-кода официального сайта `kubmi.ru`.
    *   `KubMiDatabase`: локальное хранилище данных.
    *   `Repositories`: реализуют логику выбора источника данных (сеть или БД) и кэширования.
2.  **Domain Layer (Доменный слой):**
    *   Содержит бизнес-модели (`News`, `ScheduleItem`, `WeeklyScheduleData`) и интерфейсы репозиториев.
3.  **Presentation Layer (Слой представления):**
    *   `ViewModels`: управляют состоянием экрана и обрабатывают события пользователя.
    *   `Compose Screens`: декларативное описание пользовательского интерфейса.

## 5. Подробное описание ключевых модулей

### 5.1. Веб-скрейпинг (Web Scraping)
Поскольку у института на данный момент отсутствует публичное API для расписания, я реализовал модуль `WebScraper` на базе библиотеки **Jsoup**.
*   **Логика работы:** приложение отправляет HTTP-запросы к страницам расписания, анализирует структуру DOM-дерева и извлекает данные из таблиц.
*   **Особенности:** реализована обработка сложных таблиц с объединенными ячейками (`rowspan`, `colspan`), а также автоматический обход вложенных ссылок для получения полного расписания групп и преподавателей.
*   **Оптимизация:** добавлены задержки между запросами для снижения нагрузки на сервер института.

### 5.2. Режим киоска и безопасность
Для использования приложения на терминалах института был разработан `KioskManager`.
*   **Блокировка:** реализовано подавление системных кнопок («Назад», «Домой», «Меню запущенных приложений»).
*   **Интерфейс:** автоматический переход в полноэкранный режим (Immersive Mode) и предотвращение выключения экрана.
*   **Защита:** вход в настройки приложения осуществляется через пароль, который хранится в зашифрованном виде с использованием **Android Keystore** через `EncryptedSharedPreferences`.

### 5.3. Синхронизация данных
Для поддержания актуальности данных используется **WorkManager**. Я настроил периодическую задачу `DataSyncWorker`, которая в фоновом режиме обновляет новости и расписание, даже если приложение закрыто. Это гарантирует, что при открытии пользователь увидит свежую информацию.

### 5.4. Пользовательский интерфейс (UI/UX)
Интерфейс разработан с учетом специфики медицинского вуза — строгий, чистый и функциональный стиль.
*   Использованы современные компоненты **Material 3**.
*   Реализована поддержка динамических цветов и адаптивная верстка для корректного отображения как на смартфонах, так и на больших информационных панелях.
*   Интегрирована библиотека **Coil** для эффективной загрузки и кэширования изображений новостей.

## 6. Процесс разработки (этапы)
Я разделил процесс создания приложения на следующие этапы:
1.  **Анализ и проектирование:** изучение структуры сайта `kubmi.ru`, определение ключевых сущностей данных.
2.  **Разработка ядра данных:** написание парсеров и проектирование схемы базы данных Room.
3.  **Реализация бизнес-логики:** создание репозиториев и Use Cases для управления данными.
4.  **Разработка UI:** создание экранов расписания, новостей и административной части на Jetpack Compose.
5.  **Интеграция системных функций:** реализация режима киоска и фоновой синхронизации.
6.  **Тестирование и отладка:** проверка корректности парсинга при изменении верстки сайта, нагрузочное тестирование.

## 7. Тестирование
В ходе разработки проводились следующие виды тестирования:
*   **Unit-тесты:** проверка логики парсинга HTML-кода для различных сценариев (пустые таблицы, некорректные ссылки).
*   **UI-тесты:** проверка навигации и корректности отображения данных на различных разрешениях экрана.
*   **Integration-тесты:** проверка взаимодействия Hilt, Room и WebScraper.

## 8. Заключение
Разработанное приложение является мощным инструментом для цифровизации учебного процесса в Кубанском медицинском институте. Оно решает проблему быстрого доступа к информации и может быть использовано как персонально студентами, так и централизованно на информационных стендах вуза.

Приложение готово к масштабированию и добавлению новых функций, таких как личный кабинет студента или push-уведомления об изменениях в расписании.
